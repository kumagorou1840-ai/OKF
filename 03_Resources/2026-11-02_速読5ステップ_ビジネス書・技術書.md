# 📚 紙のビジネス書・技術書を最速で読む「抽象⇄具体」5ステップ読書術

## 📌 コアエッセンス（1行要約）
- 1ページ目から順番に読むのをやめ、「抽象（全体の設計図・主張）を先に掴み、必要な具体（事例・詳細・コード）だけに降りる」往復運動によって読書速度を3〜5倍にする。

## 🛠 実践5ステップ（20分タイムアタック手順）
1. **【準備】読む前に「持ち帰るゴール」を1行で決める（1分）**
   - 「この本から何を得られたら勝ちか？」を1つだけ決めてから開く。
   - 脳に検索キーワードをセットし、無関係な8割の文章を無意識にスキップできるようにする。
2. **【抽象】「まえがき・目次・あとがき」で全体構造（核）を掴む（5分）**
   - **まえがき・あとがき**: 著者が最も伝えたい「核（コアメッセージ）」を把握する。
   - **目次**: 本全体の設計図を見て**「今の自分に重要な章（★）」を2〜3個選び**、それ以外の章は「読まない」と決める（気になるページに付箋やドッグイヤーをつける）。
3. **【抽象→具体】「見出し・太字・図解」の高速スキミング（10〜15分）**
   - 選んだ章の「見出し」「段落の最初の1文」「太字」「図表・まとめ」だけを目で追いながらページをめくる。
   - ビジネス書の8割を占める「具体例（エピソード）」は、主張（抽象）に納得できればすべて読み飛ばす。
   - **「なぜそうなる？」「具体的にどうやる？」と引っかかった箇所だけ**、ブレーキを踏んで本文（具体）を精読する。
#### 4. 【技術書特化】「既知」を飛ばし、「全体図・比較表」に変換して読む
- **未知の2割に集中**: すでに知っている概念や基礎文法の章は丸ごと飛ばす。
- **全体を図形化・表形式化する**: 文章のまま追わず、アーキテクチャや処理フローは「1枚の図（ブロック図・フロー図）」に、複数手法やメリット/デメリットは「表（テーブル）」に整理して一目で理解する。
- **コードは「入出力」と「核」だけ見る**: 1行ずつ目で追わず、「何を入力して、どう変換し、何を出力しているか」のブロック構造だけを把握する。
5. **【具体アクション】「明日から試すこと」を1つだけメモする（3分）**
   - 本を閉じる前に、「この本の核は何か（抽象）」「明日どの業務・コードで試すか（具体）」を1〜3行だけObsidianにメモして完了とする。
