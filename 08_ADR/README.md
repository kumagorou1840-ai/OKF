# ADR（アーキテクチャ決定記録）運用ガイド

技術選定や設計判断の背景・評価軸を記録し、週次・月次の振り返りで判断パターンを蓄積するための運用ルール。

---

## 1. 新規作成の流れ
1. `08_ADR/` 配下にノートを作成する。
   - 命名規則: `0001-タイトル.md`（4桁連番 + 要約）
2. テンプレート `templates/madr-template.md` を適用する。
3. プロパティを入力する。
   - `状態`: 提案中 / 承認 / 却下 / 廃止 / 置換済
   - `決定者`: 記録者名
   - `評価軸`: 重視した基準（複数指定可）
     - 例: 開発速度、保守性、ローカルファースト、コスト、移行容易性
4. 決定に伴うタスクがあれば末尾に記述する。
   - 書式: `- [ ] #tc/adr タスク名 (見積: 30m)`

---

## 2. TaskChute（デイリーノート）連携
- デイリーノート（`Diaries/` 配下）に未完了の `#tc/adr` タスクが自動集約される。
- 朝の計画時に、抽出されたタスクを本日のタイムライン（実行レール）に組み込んで消化する。
- 完了チェックを入れると、ADR側のタスクも連動して完了となる。

---

## 3. 定期レビュー（週次・月次）
- [[ADR一覧]] を開いて以下の点を確認する。
  - 保留中（提案中）の決定事項がないか。
  - どの「評価軸」が多く選ばれているか（判断の偏りや重視傾向の把握）。
  - 頻出する評価軸があれば、評価軸の標準候補として追記・統一する。
