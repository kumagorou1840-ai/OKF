# スキル原本：JSONクレンジング実装マニュアル

LLM（AI）が出力するJSONデータをシステム側で安全にパースするための、テキストクレンジング関数の実装とテストの手順です。

## 1. 発生する問題（AIの癖）
LLMが出力するJSONには、以下のような表記の揺れや雑音が含まれることがあり、そのまま `json.loads` に渡すと `JSONDecodeError` を引き起こします。
1. **大文字小文字のコードブロック**: ` ```json ... ``` ` だけでなく、` ```JSON ... ``` ` などの表記の揺れ。
2. **コードブロック指定なし**: ` ``` ... ``` ` だけで囲まれている。
3. **前後の雑音テキスト**: JSONの前後に「以下が出力結果です」「以上です」といった説明テキストが混入する。
4. **閉じタグ欠損**: ` ```json ` で開始されているが、末尾の ` ``` ` が途中で切れている。

## 2. 解決方法（正規表現による頑健な抽出）
この問題を解決するため、単純な `replace()` ではなく、正規表現（`re` モジュール）を用いた抽出・クレンジング処理を実装します。

### 実装パターン（Python）
```python
import re

def clean_json_text(text: str) -> str:
    """
    LLMの出力文字列からMarkdownコードブロック (```json ... ```) を抽出し、
    不要な文字や前後の雑音テキストを取り除いて純粋なJSON文字列を返します。
    """
    # 大文字小文字を区別せず、```(?:json)? で囲まれた最長マッチを検索
    match = re.search(r'```(?:json)?\s*([\s\S]*?)\s*```', text, re.IGNORECASE)
    if match:
        return match.group(1).strip()
    
    # 閉じタグがないが開始タグがある不完全なケースの救済
    cleaned = text.strip()
    cleaned = re.sub(r'^```(?:json)?\s*', '', cleaned, flags=re.IGNORECASE)
    cleaned = re.sub(r'\s*```$', '', cleaned)
    
    return cleaned.strip()
```

## 3. テスト駆動開発（TDD）手順
本クレンジング処理を追加または修正する際は、以下のステップでTDDを実行してください。

1. **テストケースの作成**: 
   - 正常系（通常のブロック）
   - 大文字小文字（` ```JSON `）の揺れ
   - jsonプレフィックスなし（` ``` `）
   - 前後の雑音テキスト混入
   - 未クローズのブロック
   - ブロックなし
2. **モジュールインポートの解決**:
   テスト実行時に `ModuleNotFoundError` を防ぐため、必ず環境変数 `PYTHONPATH` に対象プロジェクトディレクトリを指定してテストを実行すること。
   例: `$env:PYTHONPATH="P_Project/project_01_json_fix"; python -m unittest P_Project/project_01_json_fix/test_json_cleaner.py`
3. **RED-GREEN確認**:
   初期の単純な replace ロジック等でテストを実行し失敗（RED）することを確認した上で、正規表現による実装を適用し、オールグリーン（GREEN）になることを検証する。
