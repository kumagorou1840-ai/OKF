# BEPシミュレーション起動・運用手順書

## 1. 目的
本手順書は、損益分岐点（BEP: Break-Even Point）シミュレーションプログラムの起動・運用、データ更新、および動作テストの手順を定義し、開発者および運用担当者が迷うことなくプロジェクトを実行できる状態を担保することを目的とします。

## 2. プロジェクト構成内容（フォルダ構造）
移行されたプロジェクトフォルダ `C:\Users\PC_User\my-bep-simulation` の構造は以下の通りです。

```
my-bep-simulation/
├── data/
│   └── product_matrix.csv        # BEP算出用の基本データ（30パターン）
├── __pycache__/                  # キャッシュディレクトリ
├── agy.bat                       # 起動用バッチファイル（ローカル）
├── dashboard.html                # 可視化ダッシュボード（HTML/JS）
├── generate_dashboard.py         # ダッシュボードHTML動的生成スクリプト
├── generate_data.py              # シミュレーション用CSVデータ生成スクリプト
├── simulation.log                # シミュレーション実行時の履歴ログ
├── simulation.py                 # 並列処理・DuckDBを用いたBEP計算コアエンジン
├── simulation_results.json       # 計算結果の出力JSONデータ
└── test_simulation.py            # TDD動作確認・単体テスト用スクリプト
```

## 3. 起動方法
### 3.1 agy コマンドによる自動起動
以下の手順で、シミュレーションの実行からダッシュボードの起動までをワンクリックで実行できます。

1. コマンドライン（PowerShell またはコマンドプロンプト）を開きます。
2. ディレクトリを移動します。
   ```bash
   cd C:\Users\PC_User\my-bep-simulation
   ```
3. 起動コマンド `agy` を実行します。
   ```bash
   agy
   ```

> [!NOTE]
> `AI_company` ルート直下の `agy.bat` も配置されています。そちらを実行すると、自動的に `my-bep-simulation` に移動した上で起動シーケンスが走ります。

### 3.2 起動時に自動で行われる処理
`agy.bat` を実行すると、以下の処理がバックグラウンドで逐次実行されます。
1. **シミュレーション計算 (`python simulation.py`)**
   DuckDBメモリデータベースへCSVデータをロードし、`ThreadPoolExecutor` によるマルチスレッド並列処理で30パターンの損益分岐点を計算します。結果は `simulation_results.json` に出力され、履歴が `simulation.log` に書き込まれます。
2. **ダッシュボードHTMLの更新 (`python generate_dashboard.py`)**
   前ステップの計算結果（JSON）を元に、Plotly.js を組み込んだリッチなダッシュボード `dashboard.html` を動的に更新・再生成します。
3. **ブラウザ自動起動 (`start dashboard.html`)**
   更新されたダッシュボードがデフォルトブラウザで起動し、グラフや入力UIによるシミュレーションが可能になります。

## 4. 動作検証（TDDテスト）の実行方法
システムの完全性を保証するため、TDD（テスト駆動開発）に基づくテストコードが用意されています。

### 4.1 テストコマンド
```bash
python -m unittest test_simulation.py
```

### 4.2 検証内容
- **`test_csv_file_exists`**: データファイル（`product_matrix.csv`）が正しいパスに存在しているかを検証します。
- **`test_csv_structure_and_values`**: CSVが30行であること、列構造が正しいこと、販売単価が単位当たり変動費より大きいこと（＝限界利益がプラス）を検証します。
- **`test_simulation_run`**: 並列シミュレーションが正常終了し、`simulation_results.json` と `simulation.log` が正しく更新されるかを検証します。
- **`test_dashboard_generation`**: ダッシュボード生成スクリプトがエラーなくHTMLを出力し、Plotly CDNリンク等の必要な記述が含まれているかを検証します。

## 5. データ再生成方法
シミュレーションの元データを新規にランダム生成し、異なる製品パターンで検証を行いたい場合は、以下の手順を実行します。

### 5.1 データ再生成コマンド
```bash
python generate_data.py
```
実行すると、シード値（固定値 42）に基づいて、新しく30パターンの製品データが `data/product_matrix.csv` に自動生成されます。

### 5.2 反映手順
CSVの再生成後は、再度 `agy` を実行してシミュレーションとダッシュボードの更新を行ってください。

## 6. よっちゃん流システム診断（ハイブリッド評価）
本BEPシミュレーションシステムが提供する価値と今後の進化ベクトルを多角的に診断します。

### 📊 内部診断（核・質・特・欠）
* **核（核心）**: 並列処理とインメモリ分析（DuckDB）の融合により、多次元データでもミリ秒単位で処理できる超高速計算基盤。
* **質（品質）**: TDDによるテストケースが配置されており、ロジック変更やデータ追加の際も常に動作確認が容易であること。
* **特（特性）**: Plotly.jsを用いたフロントエンドでの動的スライダー調整により、ブラウザ上でリアルタイムに固定費や単価の感度分析ができるUX。
* **欠（欠損）**: 現状はデスクトップ完結型であり、データの入力元がローカルCSVに限られています。

### 🚀 未来の進化ベクトル（方・移・拡・新）
* **方（方向性）**: クラウドやWeb APIとの連携により、多人数での共同シミュレーション機能への移行。
* **移（移動性）**: CSVのロード部分をモジュール化し、Excel、Googleスプレッドシート、あるいは基幹データベースから直接取得できるようにする移植性。
* **拡（拡張性）**: モンテカルロシミュレーションやAI（Software 2.0/3.0）モデルを組み込み、売上数量の確率的変動を加味した不確実性分析（モンテカルロBEP）の実装。
* **新（新規性）**: LLMを組み込んだ「対話型シナリオ設計アシスタント（LLM as an OS）」の配置。例えば、「利益を10%改善するための固定費削減プランを考えて」と話しかけるだけで、ダッシュボードのスライダーが連動して最適解を示すエージェント連携機能。
