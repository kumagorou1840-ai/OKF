# 🔄 No.5 状態遷移・イベントフロー設計書

## 1. 概要

本ドキュメントは、システム全体のパイプライン状態遷移、AIサブエージェントのライフサイクル状態、および自己修復（TDDエラーフィードバック）のイベントフローを定義します。

---

## 2. Mermaid パイプライン状態遷移図

```mermaid
stateDiagram-v2
    [*] --> Idle: システム初期化

    state Idle {
        [*] --> Ready: 入力待ち
    }

    Idle --> RequirementsDefinition: ユーザー要求受領

    state RequirementsDefinition {
        [*] --> Analyzing: 課題・論点抽出
        Analyzing --> UnderstandingLock: サマリー作成
        UnderstandingLock --> WaitingUserApproval: レベル1/2スライダー判定
    }

    WaitingUserApproval --> DesignPhase: よっちゃん承認 [APPROVED]
    WaitingUserApproval --> RequirementsDefinition: 修正指示 [REJECTED]

    state DesignPhase {
        [*] --> FrameworkExpansion: SCAMPER / 6W3H / ER図作成
        FrameworkExpansion --> ArchitectureLock: 仕様確定
    }

    DesignPhase --> SurgicalImplementation: 自動進行 (Level 2/3) または 承認後 (Level 1)

    state SurgicalImplementation {
        [*] --> WorktreeIsolation: Git Worktree生成
        WorktreeIsolation --> CodeEditing: Surgical Changes実行
        CodeEditing --> SurgicalDiffCheck: 変更差分検証
    }

    SurgicalImplementation --> TestingVerification: コード編集完了

    state TestingVerification {
        [*] --> RunTests: pytest/npm test実行
        RunTests --> TestPassed: 全テストクリア
        RunTests --> SelfHealingLoop: テスト失敗検出
        
        state SelfHealingLoop {
            [*] --> SystematicDebugging: エラーログ解析
            SystematicDebugging --> ApplyPatch: 外科的パッチ適用
            ApplyPatch --> RunTests: 再検証 (Max 3回)
        }
    }

    SelfHealingLoop --> EscalatedToUser: Max試行回数超過
    EscalatedToUser --> SurgicalImplementation: 手動指示入力

    TestingVerification --> Completed: TestPassed ＆ 最終承認
    
    state Completed {
        [*] --> GenerateNotes: Obsidianノート自動出力
        GenerateNotes --> GitCommit: コミット＆Merge
    }

    Completed --> [*]
```

## 3. 自律度レベル（Level 1〜3）ごとのイベント制御分岐

| 自律度レベル | 承認ゲート発生ポイント | イベント制御挙動 |
| :--- | :--- | :--- |
| **Level 1 (手動承認モード)** | - 全ツール呼び出し時<br>- 全フェーズ切替時 | エージェントはツール呼び出し前・後で完全に一時停止し、よっちゃんの個別のWeb/CLI承認イベントを待つ。 |
| **Level 2 (半自律モード - デフォルト)** | - `UnderstandingLock` 完了時<br>- `TestingVerification` 完了時 | フェーズ内の単一ツール実行は自動連続処理し、主要成果物の完成時のみ承認ダイアログをトリガー。 |
| **Level 3 (完全自律モード)** | - `EscalatedToUser` (自己修復失敗時) のみ | 全フェーズを自動走破。自己修復が3回失敗した場合のみ、非常停止しよっちゃんへ通知。 |

---

## 4. 例外・自己修復フロー仕様

1. **Self-Healing Trigger**: テストコマンドの Exit Code ≠ 0 を検知。
2. **Log Extraction**: エラーのスタックトレースを自動抽出し、`systematic-debugging` コンテキストをロード。
3. **Patch Execution**: 該当の最小ブロックのみを `replace_file_content` で修復。
