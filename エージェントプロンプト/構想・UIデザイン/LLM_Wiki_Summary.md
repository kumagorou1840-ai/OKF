## 1. 「核・質・特・欠」によるシステム診断

### 【核】(Core / 本質)
LLM Wikiの核心は、知識を「その場限りの検索（RAG）」から**「永続的なコンパイル（Wiki）」**へと転換することにある。情報は単に断片として取り出されるのではなく、既存の知識体系の中に「統合」され、リンクされ、常に最新の状態に「ビルド」され続ける。

### 【質】(Quality / 品質)
Obsidianを「IDE」、LLMを「プログラマー」、Wikiを「コードベース」と見なすメタファーが非常に強力である。Markdownという疎結合なテキスト形式を採用することで、人間が読みやすく、かつLLMが編集しやすい、高純度なフィードバックループを実現している。

### 【特】(Characteristics / 特徴)
「知識の複利（Compounding）」が最大の特徴。新しい情報を入れるたびに、既存のページとの矛盾が指摘され、関連性が強化される。ファンWiki（Tolkien Gateway等）のような膨大な体系を、一人の人間がLLMという「専属の司書」を使って構築できる拡張性を持つ。

### 【欠】(Missing / 課題)
LLMによる自動メンテナンスの「精度」と「一貫性」の維持が課題。大規模になると、LLMがWiki全体のコンテキストをどう把握し続けるかという「コンテキスト窓」の制約や、誤った統合（ハルシネーション）をどう検知するかというガードレールが必要になる。

## 2. 要約：ホップ・ステップ・ジャンプ

### 👟 ホップ：従来の限界と「使い捨て」の知識
従来のRAG（検索拡張生成）は、質問のたびにゼロから関連情報を探し出す「その場しのぎ」の仕組みである。どれだけ多くの資料を読み込ませても、LLMの中に知識が積み上がることはなく、複雑な文脈や複数の資料をまたぐ統合的な回答には限界があった。

### 🏃 ステップ：LLMによる「永続的Wiki」の構築
LLM Wikiは、LLMに「Wikiの保守」という重労働（要約、相互参照、記録）をすべて任せる。新しいソースが追加されると、LLMはそれを単に検索用に索引化するのではなく、既存のMarkdownファイル群を書き換え、エンティティを更新し、知識を構造化して統合する。これにより、知識は「読み捨て」ではなく「資産」へと変わる。

### 🚀 ジャンプ：人間とAIの共創による「知の外部脳」
最終的に、Wikiは人間とLLMが対話を通じて育て上げる「進化し続ける成果物」となる。人間は問いを立て、ソースを選定する「探検家」に徹し、LLMはそれを整理・統合する「建築家」となる。この共生により、個人の健康、研究、ビジネス、あるいは読書体験が、何千ものリンクで結ばれた強固な「知の宇宙」へと昇華される。
