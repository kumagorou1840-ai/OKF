# 🔒 No.12 セキュリティ・認証・アクセス制御設計書

## 1. 概要

本ドキュメントは、AIエージェント自動化システムにおける機密情報（APIキー、ソースコード、Vaultノート）の保護原則、エージェントへの最小権限適用（Least Privilege）、およびユーザー権限管理モデルを定義します。

---

## 2. セキュリティ原則と権限境界

```text
[User (Yocchan)] --------> [Auth & RBAC Gate] --------> [Agent Core]
   (Master Admin)               │                         │
                                ▼                         ▼
                     [Encrypted Credentials]    [Sandbox Worktree]
                       (API Keys / `.env`)     (Restricted File Access)
```

### 2.1 エージェントへの最小権限原則 (Principle of Least Privilege)
1. **File System Boundaries**: エージェントのファイル操作権限は、指定された `Worktree` パスおよび Obsidian Vault の特定の出力フォルダ配下に制限。
2. **Tool Execution Scope**: 破壊的コマンド（`rm -rf`, `git push --force` 等）は定義レベルで遮断。
3. **Surgical Scope Limit**: ソースコード書き換え時は指定の行範囲外への書き込みを拒否。

---

## 3. 認証・秘密情報管理 (Credential Management)

1. **環境変数の秘匿**: APIキー（OpenAI / Anthropic / GCP）はソースコード内にハードコーディングせず、ローカルの `.env` または Windows 資格情報マネージャーに保管。
2. **Git コミット除外**: `.gitignore` に `.env`, `scratch/`, `.worktrees/`, `transcript.jsonl` を明記し、リポジトリへの誤アップロードを防止。

---

## 4. ロールベースアクセス制御 (RBAC)

| ロール名 | ユーザー/エージェント | 権限範囲 |
| :--- | :--- | :--- |
| **System Admin** | よっちゃん (人間) | 全権限（自律度切り替え、パイプライン緊急停止、最終コミット承認）。 |
| **Architect Agent** | AIサブエージェント | 設計ドキュメント・Mermaid図の生成（Read-Only ソースコード参照）。 |
| **Coder Agent** | AIサブエージェント | 孤立 `Worktree` 内のコード編集（外科的変更のみ）。 |
| **Test Runner** | 評価サブエージェント | テストコマンドの実行と結果ログの読み取り（書き込み不可）。 |
