# 🧪 No.10 単体・統合テスト計画書

## 1. 概要

本ドキュメントは、システム全体の品質と自律修復機能を検証するための**単体テスト (Unit Test)**、**結合テスト (Integration Test)**、および **エージェント自己修復 TDD 試行テスト計画**を定義します。

---

## 2. テストフェーズと対象一覧

```text
[Unit Tests] -------------> [Integration Tests] -------------> [Self-Healing TDD Test]
- Data Model Validation    - API Endpoint Verification    - Auto Bug Injection
- Surgical Diff Check      - WebSocket Log Streaming      - Agent Self-Correction Loop
- Worktree Creation        - Level 1-3 Gate Behavior      - Approval Escalation
```

---

## 3. 主要テストケース仕様表

| ケースID | 分類 | テスト項目・目的 | 実行手順・入力 | 期待される結果 (Acceptance Criteria) |
| :--- | :--- | :--- | :--- | :--- |
| **TC-01** | 単体 | Surgical Diff の厳格性検証 | ターゲット行外の文字を1文字変更したコードを入力 | `SurgicalViolationError` が発生し変更が安全に拒否されること。 |
| **TC-02** | 単体 | Git Worktree アイソレーション | `create_isolated_worktree()` を呼び出し | `.worktrees/` 配下に隔離ブランチが正常生成されること。 |
| **TC-03** | 結合 | Level 1 承認ゲート動作確認 | パイプラインを Level 1 で起動しツール呼出 | `WAITING_APPROVAL` 状態となり、承認指示なしでは進行しないこと。 |
| **TC-04** | 結合 | Level 2 自動進行とフェーズ承認 | パイプラインを Level 2 で起動しフェーズ終了 | 各フェーズ完了時のみよっちゃんの承認待ち状態になること。 |
| **TC-05** | 統合 | 自己修復 (Self-Healing) ループ | あえてテスト失敗するバグコードを注入 | エージェントがエラーログを解釈し、最大3回以内に自力でコード修正して `pytest` をPassさせること。 |
| **TC-06** | 統合 | 非常停止 (Emergency Stop) | 処理実行中に停止ボタンを押下 | 全サブエージェントプロセスが即座に停止し、Worktreeが退避されること。 |
